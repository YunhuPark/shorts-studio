# 오픈소스 결정 기록

검증 기준일: 2026-10-29. 수치는 `gh api repos/<repo>`로 읽은 값이다. 라이선스 원문은 앞부분만 읽은 항목이 있어 "미확인"으로 표시했다.

## 2026-10-29 영상 렌더 엔진 (컷 이미지 + 음성 + 자막 + 음악 → 9:16 mp4)
- 제약: 서버에서 다중 사용자 렌더, 상업 서비스, 한국어 자막, 소수점 단위로 부드러운 카메라 이동.
- 후보:
  - FFmpeg + Pillow 직접 구성 (현재 `build_v2.py`) — 외부 라이브러리 추가 없음
  - MoviePy — MIT, ★15,052, 마지막 push 2026-08-26
  - Remotion — ★68,711, push 2026-10-28, 라이선스 `NOASSERTION`(자체 라이선스)
  - editly — MIT, ★5,571, 마지막 push 2025-05-12
- 채택: **FFmpeg(서브프로세스) + Pillow 직접 구성 유지**
  - 이유: 이미 동작하고, 흔들림을 측정해 검증했다(떨림 0.073→0.0007px). MoviePy와 editly가 줄여줄 코드가 거의 없고, 둘 다 프레임 단위 소수점 카메라를 직접 지원하지 않는다.
- 버린 후보와 이유:
  - Remotion: 무료 라이선스는 개인, 직원 3명 이하 영리 조직, 비영리, 평가 목적에 한정된다. 그 이상은 회사 라이선스가 필요하다. 다른 사람에게 렌더를 제공하는 서비스가 무료 범위에 드는지는 원문에서 확인하지 못했다. 5.0에서 약관이 바뀐다고 적혀 있다. 라이선스 불확실성이 크다.
  - editly: 마지막 업데이트가 5개월 전이고 기능이 얇다.
  - MoviePy: 필요한 부분을 이미 구현했다. 나중에 편집 UI가 필요하면 재검토.
- 라이선스 주의:
  - FFmpeg는 기본 LGPL 2.1+, `--enable-gpl`로 빌드하면 GPL v2+가 된다. libx264를 쓰는 빌드는 GPL일 수 있다(빌드 구성은 미확인).
  - 서버에서 별도 프로세스로 호출하고 바이너리를 사용자에게 배포하지 않으면 보통 배포 의무가 생기지 않는다. 데스크톱 앱으로 배포하게 되면 다시 검토한다.
- 적용 후 확인: 서버 렌더 시간 측정(이 PC 기준 21컷 약 5분 21초), 동시 2작업 부하 테스트.

## 2026-10-29 작업 큐 (이미지/음성/렌더 비동기 작업)
- 제약: Python 백엔드, 재시도와 취소, 비용 상한, 초기에는 인프라를 적게.
- 후보:
  - Postgres 작업 테이블 + 워커(`FOR UPDATE SKIP LOCKED`) 직접 구현
  - Celery — ★29,096, push 2026-10-28, SPDX `NOASSERTION`(LICENSE 앞부분 저작권 고지만 확인, 라이선스 종류는 미확인)
  - BullMQ — MIT, ★9,558 (Node 전용)
  - Temporal — MIT, ★24,054 (운영 부담 큼)
- 채택: **MVP는 Postgres 작업 테이블 직접 구현**, 규모가 커지면 Celery로 이행
  - 이유: 이미 필요한 Postgres만으로 되고(Supabase), 작업 종류가 5개뿐이라 100줄 안팎이다. Redis 같은 인프라를 늘리지 않는다.
- 버린 후보와 이유: BullMQ는 Node 전용이라 Python 렌더 코드와 맞지 않는다. Temporal은 MVP에 과하다.
- 라이선스 주의: Celery를 쓰게 되면 라이선스 원문 전체와, 브로커로 쓸 Redis의 라이선스 변경 이력(Valkey 같은 대안)을 확인한다. 이 부분은 미확인.

## 2026-10-29 인증, DB, 파일 저장
- 후보:
  - Supabase — Apache-2.0, ★114,278, push 2026-10-29 (Postgres + Auth + Storage)
  - Better Auth — MIT, ★30,510 (인증만)
  - Auth.js(next-auth) — ISC, ★28,376, 마지막 push 2026-07-22
  - MinIO — AGPL-3.0, **archived=true**, 마지막 push 2026-04-24
  - SeaweedFS — Apache-2.0, ★35,796
  - 직접 구현
- 채택: **Supabase로 시작** (관리형 사용, 필요하면 자체 호스팅 가능)
  - 이유: 인증, DB, 파일 저장을 한 번에 얻는다. 인증을 직접 만드는 비용과 보안 위험을 피한다.
- 버린 후보와 이유: MinIO는 AGPL에 저장소가 보관(archived)되어 새로 채택할 이유가 없다. Better Auth와 Auth.js는 인증만 해결해서 DB와 저장소를 따로 붙여야 한다.
- 라이선스 주의: Supabase 자체는 Apache-2.0. 관리형 서비스의 요금과 약관은 별도로 확인.

## 2026-10-29 한국어 음성 자체 운영 (2단계, GPU 서버 전제)
- 후보:
  - CosyVoice(`QwenAudio/CosyVoice`) — Apache-2.0, ★24,184, push 2026-05-25, README에 한국어 지원 명시
  - MeloTTS — MIT, ★7,686, 한국어 예시 있음, **마지막 push 2024-12-24**
  - F5-TTS — 코드 MIT, ★15,479, **사전학습 모델은 CC-BY-NC**
  - Fish Speech — ★33,461, **Fish Audio Community License / Research License**
  - Coqui TTS — MPL-2.0, ★46,164, 마지막 push 2024-08-16
- 채택: **MVP는 API(Azure, ElevenLabs)를 쓰고, 자체 운영 단계에서 CosyVoice를 1순위로 평가**
  - 이유: 코드 라이선스(Apache-2.0)와 한국어 지원이 확인됐고 업데이트도 최근이다.
- 버린 후보와 이유:
  - F5-TTS: 모델이 비상업 라이선스라 서비스에 쓸 수 없다.
  - Fish Speech: 자체 커뮤니티 라이선스와 연구용 라이선스가 섞여 있어 상업 이용 조건이 불분명하다.
  - MeloTTS: 상업 사용은 가능하지만 약 10개월째 업데이트가 없고, 품질은 "기본 읽기" 수준일 가능성이 있다(들어보지 못했다).
  - Coqui TTS: 2024년 이후 업데이트가 없다.
- 라이선스 주의: CosyVoice **모델 가중치의 라이선스는 확인하지 못했다.** 코드와 가중치 라이선스가 다를 수 있으니 채택 전에 반드시 확인.
- 적용 후 확인: 같은 대사로 Azure/ElevenLabs/CosyVoice 샘플을 만들어 사용자 청취 비교. (소리는 사람이 판단.)

## 2026-10-29 자막 폰트
- 후보: Pretendard(`orioncactus/pretendard`, ★3,638, push 2026-07-23), Noto Sans KR, 현재 맑은 고딕(윈도우 시스템 폰트)
- 채택: **Pretendard 또는 Noto Sans KR로 교체**
  - 이유: 현재 스크립트의 `C:\Windows\Fonts\malgunbd.ttf`는 서버 서비스에 재배포·사용하기에 라이선스상 곤란할 수 있다.
- 라이선스 주의: Pretendard의 LICENSE 전문을 읽어 SIL OFL 1.1임을 확인했다(2026-10-29). 소프트웨어에 포함·재배포 가능하되 각 사본에 저작권 고지와 라이선스를 동봉해야 하고, 폰트 단독 판매는 금지된다. 폰트로 만든 문서(영상 포함)에는 라이선스 제약이 적용되지 않는다고 명시돼 있다. 라이선스 사본은 `assets/fonts/Pretendard-LICENSE.txt`. Noto Sans KR도 OFL로 알려져 있으나 이번에 검증하지 않았다.
- 적용 후 확인: `Pretendard-Bold.otf`(1,576,660바이트, 크기 일치)를 `assets/fonts`에 두고 렌더러가 맑은 고딕보다 우선 사용함을 테스트로 확인. 자막 1줄 폭이 좁아져 "오늘이 우리 결혼기념일이라서"가 한 줄에 들어온다.
